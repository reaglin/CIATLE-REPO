## 1. Two discipline keys were colliding — a live data defect

Discipline keys were generated by truncating the discipline name to 20 characters, which produced
**two pairs of identical keys**. `TaxonomyNode.Key` is the primary key, and `UpsertNodeAsync`
does `FindAsync([json.Key])` — so the second node of each pair did not create a node, it
**overwrote the first one's name and absorbed its children.**

| Colliding key | The two disciplines | Effect in the database |
|---|---|---|
| `FOREIGN_LANGUAGE__AM` | Amerindian Languages / American Sign Language And Interpreting | one node, named for ASL, holding all 4 prefixes (AYM, CMM, ASL, INT) |
| `FOREIGN_LANGUAGE__CA` | Caribbean Languages / Catalan Language | one node, named for Catalan, holding all 7 prefixes |

**Fixed** by giving the second of each pair a distinct key (`FOREIGN_LANGUAGE__ASL`,
`FOREIGN_LANGUAGE__CATALAN`). The schema allows 100 characters, so the 20-char truncation was a
generator choice, not a constraint. On redeploy the seed creates the two new nodes and re-parents
their prefixes; the original keys revert to their correct names and children.

⚠ **Any future taxonomy generation must check for key collisions.** `audit_taxonomy.py` now does.

### ⚠ `PGY` was the worst one: wrong name *and* wrong parent

`PGY` was named **"Plant Pathology"** and filed under Ornamental/Horticultural Science. In Florida
SCNS, **`PGY` is Photography** (Plant Pathology is `PLP`). The handbook confirms it, and so does
this repository's own content: eight published PGY guides — `PGY1100C` Analog Photography,
`PGY1201C` Studio and Location Lighting, `PGY1800C`, `PGY1802C`, `PGY2210C` Professional Studio
Portraiture, `PGY2470C`, `PGY2750C`, `PGY2806C` — are all photography courses that were sitting
under a horticulture discipline on the live site.

A new `Photography` discipline node was added to hold it. Two names were corrected
(`PGY` → Photography, `ROT` → Reactor Operator Technology); all other name changes were left alone.

## 3. What was deliberately NOT changed

### The 93 substantive + 295 cosmetic name changes in `TAXONOMY_SCNS_PROPOSAL.md`
Still **awaiting Ron's review**. Ron reviewed the previous name round personally, and names carry
judgment (his `EMC`/`EML` edit is the precedent). Parentage is objective; names are not.

### ~110 foreign-language prefixes — the handbook is *coarser* than we are
The parsed handbook assigns **110 prefixes** to a single flat `FOREIGN LANGUAGE EDUCATION`
discipline. The current tree splits them into Arabic / Caribbean / East Asian / Germanic / Slavic /
South Asian / Sub-Saharan African / Spanish / French / Italian / Portuguese / Catalan / Amerindian /
ASL groupings, which is **more useful for browsing** and no less correct. **Kept as-is.**

### Cases where our tree is more specific than the handbook
`Education: Exceptional Child`, `Education: Counseling Services`, `Education: Career/Technology`,
`Education: Administration And Supervision`, `Mechanics: Auto/Bod/Diesel/Marine/Sm.Eng.`, and
`Engineering: General/Support` are all finer-grained than the handbook's `EDUCATION SYSTEMS` /
`MECHANICAL ENGINEERING` / `ENGINEERING TECHNOLOGIES`. **Kept.**

### ⚠ The parsed handbook map has its own errors — do not bulk-apply it
`scns_prefix_map.json` is a PDF parse and inherits PDF-parse defects. Confirmed bad rows:

| Prefix | Map says | Reality |
|---|---|---|
| `ART`, `ARE`, `ARH`, `ARV` | discipline **Architecture** | these are Art / Art Education / Art History; the parser missed the `ART` discipline heading and absorbed them into the preceding `ARCHITECTURE` block. `ART`'s parsed title is literally `- 006`. |
| `ACR` (HVACR Technology) | discipline **Humanities** | HVACR |
| `LAW`, `JRM` | discipline **Latin American Studies** | Law |

Same absorption bug as the taxonomy's own. **Use the map as a signal to find suspect placements,
never as an authority to overwrite them.** The 34 fixes above were each checked by hand.
